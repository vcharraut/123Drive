# py123d dataset conversion commands (Waymo Motion, nuPlan, nuPlan mini)

This quick doc gives complete commands to convert:
- Waymo Open Motion Dataset (`wod-motion`)
- nuPlan (`nuplan`)
- nuPlan mini (`nuplan-mini`)

The conversion CLI is:

```bash
py123d-conversion
```

## 1) Install dependencies

From repo source:

```bash
pip install -e .[dev,nuplan,waymo]
pip install "nuplan-devkit @ git+https://github.com/motional/nuplan-devkit/@nuplan-devkit-v1.2"
```

If you prefer minimal extras, install only what you need:

```bash
# only nuPlan conversion extras
pip install -e .[nuplan]
pip install "nuplan-devkit @ git+https://github.com/motional/nuplan-devkit/@nuplan-devkit-v1.2"

# only Waymo conversion extras
pip install -e .[waymo]
```

## 2) Set required dataset/output paths

The converter reads these env vars from `src/py123d/script/config/common/default_dataset_paths.yaml`.

```bash
# output root (py123d logs/maps/sensors will be written here)
export PY123D_DATA_ROOT=/data/py123d

# nuPlan inputs
export NUPLAN_DATA_ROOT=/data/nuplan/dataset
export NUPLAN_MAPS_ROOT=/data/nuplan/maps
export NUPLAN_SENSOR_ROOT=/data/nuplan/sensor_blobs

# Waymo Open Motion input
export WOD_MOTION_DATA_ROOT=/data/waymo_open_motion
```

## 3) Complete conversion commands

### Waymo Open Motion Dataset -> py123d

```bash
py123d-conversion 'datasets=["wod-motion"]'
```

Only selected splits (example: train + val):

```bash
py123d-conversion 'datasets=["wod-motion"]' 'datasets.wod-motion.splits=["wod-motion_train","wod-motion_val"]'
```

### nuPlan -> py123d

```bash
py123d-conversion 'datasets=["nuplan"]'
```

Only selected splits (example: train + val):

```bash
py123d-conversion 'datasets=["nuplan"]' 'datasets.nuplan.splits=["nuplan_train","nuplan_val"]'
```

### nuPlan mini -> py123d

```bash
py123d-conversion 'datasets=["nuplan-mini"]'
```

Only selected splits (example: train only):

```bash
py123d-conversion 'datasets=["nuplan-mini"]' 'datasets.nuplan-mini.splits=["nuplan-mini_train"]'
```

## 4) Useful options (Hydra overrides)

You can append these to any command above.

### A) Override paths without env vars

```bash
py123d-conversion 'datasets=["nuplan-mini"]' \
  dataset_paths.py123d_data_root=/data/py123d \
  dataset_paths.nuplan_data_root=/data/nuplan/dataset \
  dataset_paths.nuplan_maps_root=/data/nuplan/maps \
  dataset_paths.nuplan_sensor_root=/data/nuplan/sensor_blobs
```

Waymo Motion path override:

```bash
py123d-conversion 'datasets=["wod-motion"]' \
  dataset_paths.py123d_data_root=/data/py123d \
  dataset_paths.wod_motion_data_root=/data/waymo_open_motion
```

### B) Force / skip re-conversion

Defaults are `true` in `default_conversion.yaml`.

```bash
# skip already converted maps/logs
py123d-conversion 'datasets=["nuplan"]' force_map_conversion=false force_log_conversion=false
```

### C) Storage mode for sensors

Global keys in `default_conversion.yaml` exist:
- `pinhole_camera_store_option`: `path | jpeg_binary | png_binary | mp4`
- `lidar_store_option`: `path | path_merged | laz_binary | draco_binary`

For `nuplan` / `nuplan-mini`, use dataset-local overrides (these are the effective ones):

```bash
py123d-conversion 'datasets=["nuplan"]' \
  datasets.nuplan.dataset_converter_config.pinhole_camera_store_option=jpeg_binary \
  datasets.nuplan.dataset_converter_config.lidar_store_option=laz_binary

py123d-conversion 'datasets=["nuplan-mini"]' \
  datasets.nuplan-mini.dataset_converter_config.pinhole_camera_store_option=mp4 \
  datasets.nuplan-mini.dataset_converter_config.lidar_store_option=draco_binary
```

If you want permanent defaults, edit `nuplan.yaml` / `nuplan-mini.yaml`.

### D) Execution backend / parallelism

Default execution is Ray (`config/common/execution/ray_executor.yaml`).

```bash
# force simple sequential mode (debug)
py123d-conversion 'datasets=["nuplan-mini"]' execution=sequential_executor

# thread pool with explicit workers
py123d-conversion 'datasets=["wod-motion"]' execution=thread_pool_executor execution.max_workers=16

# process pool with explicit workers
py123d-conversion 'datasets=["wod-motion"]' execution=process_pool_executor execution.max_workers=16
```

## 5) Notes specific to these datasets

- `wod-motion` support is marked as not fully supported yet in `docs/datasets/wod_motion.rst`.
- `nuplan` and `nuplan-mini` docs note that default conversion may store sensor file paths in logs instead of embedding binary payloads.
- Output structure is rooted at `${PY123D_DATA_ROOT}`:
  - `logs/`
  - `maps/`
  - `sensors/`

## 6) One-line quick starts

```bash
# Waymo Motion
PY123D_DATA_ROOT=/data/py123d WOD_MOTION_DATA_ROOT=/data/wod_motion py123d-conversion 'datasets=["wod-motion"]'

# nuPlan
PY123D_DATA_ROOT=/data/py123d NUPLAN_DATA_ROOT=/data/nuplan NUPLAN_MAPS_ROOT=/data/nuplan/maps NUPLAN_SENSOR_ROOT=/data/nuplan/sensor_blobs py123d-conversion 'datasets=["nuplan"]'

# nuPlan mini
PY123D_DATA_ROOT=/data/py123d NUPLAN_DATA_ROOT=/data/nuplan NUPLAN_MAPS_ROOT=/data/nuplan/maps NUPLAN_SENSOR_ROOT=/data/nuplan/sensor_blobs py123d-conversion 'datasets=["nuplan-mini"]'
```

## 7) Complete config list (what you can override)

This section summarizes the available Hydra config groups and keys used by `py123d-conversion`.

### A) Config groups (selectable presets)

You can switch these groups with `group=name` syntax.

- `execution`: `ray_executor`, `thread_pool_executor`, `process_pool_executor`, `sequential_executor`
- `log_writer`: `arrow_log_writer`
- `map_writer`: `arrow_map_writer`
- `datasets` (all available conversion datasets in this repo):
  - `av2-sensor`
  - `kitti360`
  - `nuplan`
  - `nuplan-mini`
  - `nuscenes`
  - `nuscenes-mini`
  - `nuscenes-interpolated`
  - `nuscenes-interpolated-mini`
  - `pandaset`
  - `wod-motion`
  - `wod-perception`

Example:

```bash
py123d-conversion 'datasets=["nuplan"]' execution=thread_pool_executor log_writer=arrow_log_writer map_writer=arrow_map_writer
```

### B) Top-level conversion keys (`default_conversion.yaml`)

- `logger_level`: `debug | info | warning | error`
- `terminate_on_exception`: `true | false`
- `force_map_conversion`: `true | false`

- `fisheye_mei_camera_store_option`: `path | jpeg_binary | png_binary | mp4`

## 8) All py123d datasets that support 2D data

In this section, **2D data** means non-sensor annotations such as:
- map information (`dataset_converter_config.include_map`)
- bounding boxes (`dataset_converter_config.include_box_detections`)

This ignores whether camera/LiDAR sensors are included.

### Datasets with map + bounding boxes

- `av2-sensor`
- `kitti360`
- `nuplan`
- `nuplan-mini`
- `nuscenes`
- `nuscenes-mini`
- `nuscenes-interpolated`
- `nuscenes-interpolated-mini`
- `wod-perception`
- `wod-motion`

### Quick conversion commands (map + bounding boxes)

```bash
py123d-conversion 'datasets=["av2-sensor"]'
py123d-conversion 'datasets=["kitti360"]'
py123d-conversion 'datasets=["nuplan"]'
py123d-conversion 'datasets=["nuplan-mini"]'
py123d-conversion 'datasets=["nuscenes"]'
py123d-conversion 'datasets=["nuscenes-mini"]'
py123d-conversion 'datasets=["nuscenes-interpolated"]'
py123d-conversion 'datasets=["nuscenes-interpolated-mini"]'
py123d-conversion 'datasets=["wod-perception"]'
py123d-conversion 'datasets=["wod-motion"]'
```
